| F10 | `src/ops-dashboard`, `infra/keycloak`, `infra/caddy` | Chain of real issues surfaced building the first human-SSO frontend: (a) Keycloak 26's declarative User Profile silently drops undeclared custom user attributes (`oid`) — fixed via a `null_resource` local-exec enabling `unmanagedAttributePolicy: ENABLED`, encoded in Terraform not left as tribal knowledge; (b) Keycloak's session cookies are `Secure`-flagged, silently dropped over plain HTTP for any hostname other than literally `localhost` — required standing up real local HTTPS via Caddy's internal CA (`infra/caddy/`), not just a reverse proxy; (c) `/logout` only cleared the ops-dashboard's own session, leaving Keycloak's SSO session alive so the next `/login` silently re-authenticated as the same user — fixed with RP-initiated logout (`id_token_hint` + `valid_post_logout_redirect_uris`); (d) Keycloak generated `http://` URLs in its own login pages despite being reached over HTTPS, because it didn't trust Caddy's `X-Forwarded-Proto` — fixed via `KC_PROXY_HEADERS: xforwarded`; (e) Python's `socket.getaddrinfo` (unlike `curl`/browsers) doesn't auto-resolve `*.localhost` on this Windows box — required explicit hosts-file entries. | F11 | `src/ops-dashboard` (`clients.py`, `api.py`), `rfq_common.masterdata_client` | `/map` took **49 seconds** to load (caught via a HAR capture from a real browser session, not a synthetic test). Fixed: switched every default base URL (TMS/Rate/FX/Masterdata clients) from `localhost` to `127.0.0.1`. `/map` now loads in ~1s. | this session |
