# API contracts — every API has an `openapi.yaml`

**Standard: every system API publishes an OpenAPI 3.1 spec.** FastAPI generates it
from the Pydantic models + routes; it is **committed** as the contract-of-record at
`../../systems/<system>/openapi.yaml` (exported at build, not hand-authored).

## Why committed, not just live

- **One shared action vocabulary** — each operation is bound to a domain action via
  extensions, so API, MCP, agent, and Cedar artifacts reference the same names.
- **Client-gen + Swagger UI** off a stable file; diffable in review.
- **Contract test** — assert the generated spec matches the committed one (drift gate),
  mirroring cpm-eaop's `--check` discipline.

## Required extensions on operations

```yaml
paths:
  /rfqs/{rfqId}/carrier-quotes:
    post:
      operationId: requestCarrierQuote
      x-domain-action: carrier-quote.request     # -> business/actions.yaml
      x-resource-type: RFQ                        # -> authz-projection.yaml
      x-authz-context: [rfq_region]               # context fields the PDP needs
```

`x-domain-action` / `x-resource-type` / `x-authz-context` tie the HTTP surface to the
authorization model — the same triple the MCP tools and Cedar policies use.

## Documenting a cross-service dependency: `x-consults`

OpenAPI has no native construct for "this endpoint calls another API
internally" (it describes the exposed HTTP interface, not server-side
implementation; the 3.1 `links` object is for client-side response->request
chaining, not this). ADR-010 (masterdata must be consumed via API, never a
duplicated file) is exactly this kind of dependency and was previously only
documented in prose (`mock_fx/api.py`'s docstring), invisible to the spec
itself. Use `x-consults` -- a list, since an operation can depend on more
than one other service:

```yaml
paths:
  /exchange-rates/{base}/{quote}:
    get:
      x-consults:
        - service: masterdata
          endpoint: "GET /currencies/{code}"
          purpose: "validate base/quote are known currencies (ADR-010, fail closed)"
```

Same spirit as `x-domain-action` etc: makes a real, load-bearing dependency
machine-readable and diffable instead of only living in a docstring someone
has to already know to go read.
